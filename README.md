# ecommerce-kv-prompt

一个面向电商产品图、包装图、概念图和文字参数的电商 KV 提示词系统生成技能。

它先整理产品事实，再生成一套保持产品与品牌一致性的中英双语海报提示词，适用于主 KV、生活场景、工艺概念、细节特写、参数展示和使用指南等内容。技能本身负责识别、规划和编写提示词，不会调用外部图像生成 API。

## 它解决什么问题

单独写一张海报提示词并不难，难的是让多张海报始终像同一个品牌的完整视觉系统。产品颜色可能漂移，包装文字和 LOGO 位置可能变化，中文和英文可能无法配对，不同场景的负面词也容易被重复套用。

本技能把产品识别报告作为整套 KV 的事实基础，后续海报统一引用产品外观、配色、材质、文案、LOGO 位置和品牌调性。这样可以减少产品失真、信息错写和系列视觉不一致的问题。

## 核心能力

- **产品识别**：从图片中提取品牌、品类、规格、卖点、配色、设计风格、受众、参数和材质等信息，也支持无图时根据文字资料建立识别报告。
- **事实与推断分离**：可见文字、颜色和形态与基于品类或包装语言的推断分开记录。图片中看不清的内容标记为“未识别”，不会用想象补齐。
- **风格与排版决策**：从 7 种视觉风格和 6 种文字排版方式中给出主推与备选，并说明选择依据。
- **系列化 KV 规划**：默认规划 10 张分工明确的海报，覆盖产品展示、场景、概念、细节、品牌、参数和使用信息。
- **中英双语提示词**：中文提示词与英文 Prompt 逐项对应，不把英文写成中文摘要，画面文字按统一的双语规则配对。
- **针对性负面词**：每张海报单独配置 20 至 30 个负面词，根据主 KV、生活场景、参数表等不同画面的失败模式进行调整。
- **结构化交付**：同时输出人读友好的 Markdown 和结构化 JSON，便于复核、编辑和后续处理。

## 工作流程

1. **判断输入方式**：有产品图时读取产品或包装图，无图时使用用户提供的文字资料。无图场景至少需要产品名、品类、主色调和 3 条核心卖点。
2. **完成产品识别**：按照 `references/recognition-rubric.md` 提取 8 类信息，并明确区分可见事实、合理推断和未识别字段。
3. **输出识别报告并确认方向**：根据品类、包装调性和目标受众推荐视觉风格与排版方式，同时确认模特、场景和数据可视化等特殊需求。
4. **确认生成配置**：默认使用 9:16 竖版、10 张海报加 LOGO 提示词、中英双语和 Markdown 加 JSON 双份输出。用户指定的画幅、张数或 JSON 需求优先。
5. **生成提示词系统**：结合海报分工、双语排版规则和负面词素材库，逐张写出完整提示词与布局说明。
6. **落盘与自检**：检查 JSON 结构、海报数量、中文提示词长度、负面词数量、双语配对、LOGO 位置和 CTA 等要求。

## 默认输出规格

| 项目 | 默认值 |
| --- | --- |
| 画幅 | 9:16 竖版，1080×1920 |
| 数量 | 10 张海报 + 1 组 LOGO 生成提示词 |
| 语言 | 简体中文 + 英文 |
| 主文档 | `<产品名>-电商KV提示词.md` |
| 结构化文件 | `<产品名>-电商KV提示词.json` |
| 中文提示词 | 每张海报 600 至 1000 字 |
| 英文 Prompt | 与中文提示词逐项对应的完整 Prompt |
| 负面词 | 每张海报 20 至 30 个，按场景单独配置 |

用户可以覆盖画幅，例如 1:1、3:4 或 16:9，也可以指定 3 张、5 张或 12 张等数量。覆盖配置应以用户要求为准，并同步调整构图和安全边界。

## 每张海报的六件套

每张海报都应独立包含以下内容，不能用“同前”代替：

1. 600 至 1000 字中文提示词。
2. 与中文逐项对应的英文 Prompt。
3. 20 至 30 个与当前场景相关的负面词。
4. 排版布局说明，包括文字位置、字号层级、颜色、字体风格和双语格式。
5. 明确的 LOGO 位置。默认统一在左上角，除非用户另有指定。
6. CTA 的文案、位置和样式，默认使用 `中文 ENGLISH →` 形式。

所有生成的海报都应保持产品还原度，尤其是包装设计、颜色、LOGO 位置、文字内容、图案元素和材质质感。整套海报应保持中英文字段成对出现、LOGO 位置一致，并为每个场景编写有针对性的负面词。涉及参数、成分、规格、注意事项和储存方式时，应按参考资料原样记录，不换算、不补写看不清的数据。

## 默认海报分工

| 编号 | 内容 | 主要作用 |
| --- | --- | --- |
| 01 | 主 KV 视觉 | 建立整套 KV 的第一视觉识别 |
| 02 | 生活或使用场景 | 展示产品的实际使用状态 |
| 03 | 工艺、技术或概念可视化 | 把可解释的卖点转化为视觉内容 |
| 04 | 整体细节特写 | 展示最有辨识度的产品细节 |
| 05 | 材质与质感特写 | 强调哑光、高光、磨砂或金属等质感 |
| 06 | 功能细节特写 | 展示结构或包装特色的使用状态 |
| 07 | 细节特写或用户评价 | 根据品类建立产品信任 |
| 08 | 品牌故事或配色灵感 | 建立情感联结并统一色彩体系 |
| 09 | 产品参数或规格表 | 呈现决策所需的硬信息 |
| 10 | 使用指南或注意事项 | 降低使用门槛并呈现必要提醒 |

## 使用方式与触发示例

适合在以下场景中使用：

- 上传产品图、包装图、渲染图或概念草图，要求生成整套电商 KV 提示词。
- 提供产品名称、品类、卖点和规格，要求在无图模式下生成提示词系统。
- 要求制作电商主视觉、商品海报提示词、详情页视觉或产品图反推提示词。
- 指定画幅、张数、是否需要模特、场景或数据可视化，并要求输出中英双语版本。
- 在课堂或团队协作中，拆分 10 张海报，检查同一产品在不同场景中的品牌一致性。

可以使用类似下面的请求触发：

```text
根据这张产品包装图，先做产品识别报告，再生成 10 张 9:16 电商 KV 提示词，输出 Markdown 和 JSON，中英双语，每张都要有独立的负面词、LOGO 位置和 CTA。
```

```text
我没有产品图片。请根据以下产品参数生成 5 张电商 KV 提示词，保持包装信息不变，并把无法确认的内容标记为“未识别”。
```

## 验证输出

生成 JSON 后，可使用仓库内的校验脚本检查结构和内容：

```bash
python3 scripts/validate_kv.py <输出目录>/<产品名>-电商KV提示词.json
```

如需同时检查配套 Markdown 的识别报告、LOGO 小节和 01 至 10 海报小节：

```bash
python3 scripts/validate_kv.py <输出目录>/<产品名>-电商KV提示词.json <输出目录>/<产品名>-电商KV提示词.md
```

返回码为 `0` 表示全部通过，返回码为 `1` 表示发现问题，返回码为 `2` 表示命令用法错误。校验脚本会检查顶层结构、海报数量、六件套、中文提示词长度、负面词数量与重复、双语成对、产品还原约束，以及 Markdown 的关键小节。

## 局限与质量说明

- 图片识别依赖宿主模型的多模态读取能力，不依赖外部图像生成 API。低分辨率、遮挡或角度不完整时，应补充图片或文字资料。
- 识别报告必须区分图片中直接可见的事实与合理推断。无法确认的品牌拼写、参数、认证、成分或材质不能擅自补全。
- 文生图工具对中文字符、复杂参数表和精细包装文字的还原能力可能有限。提示词可以约束排版与内容，但不能保证最终图片中的文字完全准确，发布前仍需人工核对。
- 用户评价海报只能使用不冒充真实具名用户的示例文案，参数表和注意事项应优先沿用包装或用户提供的原文。
- `validate_kv.py` 是结构与规则检查工具，不代表最终图像已经完成视觉审核，也不替代人工检查产品外观、文字准确性和品牌合规性。
